# 지금공원 — 웹 프로토타입 (v3 · 지도·그래픽 개편)

2026 한국체육산업개발(주) 공공데이터 활용 경진대회 출품작의 시연용 웹 프로토타입입니다.
**지금공원**은 공원을 고르면 그 공원의 날씨·혼잡도·코스·도감·안내를 보여 주는 서비스이고,
이번 출품작은 그중 **1차 실증 공원인 올림픽공원**을 실제 공공데이터로 구현한 것입니다.
공원에 가기 전에 **지금 걸어도 되는지 · 어느 코스로 걸을지 · 어느 문으로 들어갈지**를
네 화면(지금 · 지도 · 도감 · 안내)에서 확인하도록 만들었습니다.

바로 열기: **https://fexit2.github.io/olympic-park-walk-radar/** (GitHub Pages, 2026-11-16 공개)
로컬 파일: `index.html` (서버 없이 더블클릭해도 동작) · 정적 호스팅에 그대로 올려도 됩니다.

## 1. 네 화면

| 탭 | 화면에 두는 것 | 데이터 |
|---|---|---|
| **지금** | ① 날씨·산책 지수 히어로 그래픽(애니메이션 SVG + 원형 게이지 + 시연 모드 토글) ② 오늘의 추천 입구 1곳과 추천 코스 1개 | 기상청 단기예보(샘플) · 실시간 주차(샘플) · 주차 혼잡도 이력(실데이터) |
| **지도** | 화면 60%를 차지하는 Leaflet 지도 — 출입문 4개 레이더 펄스 핀 + 코스 Polyline, 아래에 선택한 코스 카드(네이버 지도 길찾기) | OSM 지도·보행로 · 주차 혼잡도 이력 · 좌표(카카오맵) |
| **도감** | 스팟 일러스트 4장 2열 그리드(이름 + 계절 한 줄), 탭하면 해설·위치 바텀시트 | 잔디시설정보 · FAQ · OSM · 직접 그린 일러스트 |
| **안내** | `공연 / 잔디·규정 / FAQ` 세그먼트로 한 번에 한 갈래만. 상단에 오늘 공연·잔디 상태 한 줄 | 공연정보(샘플) · 잔디시설정보 · FAQ 49건 |

한 화면에 카드를 쌓지 않습니다. 상세(코스 동선, 문별 구역, 스팟 해설, FAQ 답변, 데이터·계산)는
모두 **바텀시트**로 내려가고, 바텀시트 밖에는 핵심 2~3개만 남습니다.

### 공원 선택 (상단 칩)

브랜드 옆의 `올림픽공원 ▾` 칩을 누르면 **공원 선택 바텀시트**가 열립니다. 지금 보고 있는 공원이
강조되고, 나머지는 준비 상황을 배지로 보여 줍니다(누르면 준비 중 안내가 뜨고 화면은 그대로).

| 공원 | 상태 |
|---|---|
| 올림픽공원 | **실증 중** — 한국체육산업개발 공공데이터 8종 연동, 화면이 이 데이터로 열려 있음 |
| 미사경정공원 | 확장 예정 — 같은 기관 데이터(주차·잔디·FAQ·공연)로 연동 준비 중 |
| 분당·일산 올림픽스포츠센터 | 확장 예정 — 시설·이용 데이터, 지자체·도시공원까지 표준 스키마로 연계 예정 |

공원이 늘어나도 화면과 계산식은 그대로 두고 `api-config.js` 의 데이터 소스만 갈아 끼우는 구조입니다.

## 2. 그래픽과 모션

- **히어로**는 이미지가 아니라 인라인 SVG 한 장입니다. 해(글로우 맥동)·구름(느린 이동)·새·
  능선 3단·나무 10그루(가지 흔들림, 서로 다른 주기)·산책길·풀포기로 층을 만들고, 모드에 따라
  `--sky-a/--sky-b/--hill-mid` 와 필터가 바뀝니다.
- **비 모드**: CSS `@keyframes fall` 로 빗줄기 15개가 서로 다른 딜레이로 떨어지고,
  동시에 박물관 실루엣(불 켜진 창 6개 + 따뜻한 글로우)이 페이드 인 = "실내로 전환" 연출.
- **산책 지수 원형 게이지**: `stroke-dashoffset` 트랜지션 + 숫자 카운트업. 점수대에 따라
  초록/주황/빨강으로 바뀝니다.
- **지도 핀 레이더 펄스**: `@keyframes pulse` 로 두 겹 파동이 퍼지고, 등급색
  (원활 초록 · 혼잡 주황 · 만차 빨강 · 자료 없음 회색)을 따릅니다.
- `prefers-reduced-motion` 이면 모든 애니메이션을 끕니다.
- 스팟 일러스트 4장만 이미지이고, 나머지 그래픽은 전부 SVG/CSS 입니다.
  일러스트: `assets/spot-lonetree.png` · `spot-rose.png` · `spot-mongchon.png` · `spot-museum.png` (640×640)

## 3. 지도 — 진짜 좌표, 진짜 보행로

- **올림픽공원 실제 좌표**를 씁니다. 공원 경계·수면(88호수, 몽촌호)·산책로는
  OpenStreetMap 실측 형상이고, 출입문 4곳과 스팟 좌표는 카카오맵 장소 검색에서 확인한 값입니다
  (2026-11-16 조회).

| 지점 | 위도, 경도 | 비고 |
|---|---|---|
| 동2문 | 37.51607, 127.13004 | P1B·P2·P3·P11 |
| 남2문 | 37.51434, 127.12274 | P1A·P6·P7 |
| 북2문 | 37.52369, 127.12779 | P4·P5 |
| 서2문 | 37.52212, 127.11601 | 올림픽파크텔 주차장 — 혼잡도 등급 계산 제외 |

- **코스 Polyline 은 손으로 그린 선이 아닙니다.** 공원 보행로(footway·path·pedestrian·steps·
  cycleway·service) 노드 그래프(5,254개)에서 다익스트라 최단경로를 계산해 만든 선이고,
  칩에 적힌 거리도 그 경로의 합입니다. `tools/fetch-geo.py` 가 이 계산을 하고 결과를
  `data/geo.json` 에 저장합니다.

| 코스 | 거리 | 예상 | 동선 |
|---|---|---|---|
| 몽촌토성 산책길 | 2.5km | 35분 | 남2문 → 한성백제박물관 → 몽촌토성 → 망월봉 → 남2문 |
| 장미~나홀로나무 | 2.7km | 40분 | 동2문 → 장미광장 → 88잔디마당 → 나홀로나무 |
| 실내 문화코스 | 1.5km | 20분 | 남2문 → 한성백제박물관 → 소마미술관 → 서2문 |

  실내 문화코스 1.5km 는 네이버 지도 도보 길찾기로 같은 구간을 조회했을 때 나온
  **22분 · 1.5km · 2,314걸음**과 일치합니다(2026-11-16 확인).

- **네이버 지도 연동**: 코스 카드/바텀시트의 버튼은
  `https://map.naver.com/p/directions/{출발경도},{위도},{이름}/{도착…}/-/walk` 로 열립니다.
  핀과 스팟은 `map.naver.com/p/search/올림픽공원 {이름}` 으로 엽니다.
- **오프라인·차단 대비 2단 폴백**
  1. 타일이 막히면 → 공원 경계·수면·산책로·코스·핀을 Leaflet 벡터로만 그린 **자체 공원 지도**
     (`오프라인 지도` 배지).
  2. Leaflet 스크립트까지 막히면 → 같은 좌표로 그린 **순수 SVG 약도**(클릭 가능한 핀).
  Leaflet 1.9.4 는 `vendor/leaflet/` 에 그대로 넣어 두어 CDN 이 없어도 뜹니다.

## 4. 파일 구조

```
prototype/
├─ index.html               4개 탭 화면 골격 (이 파일을 열면 끝)
├─ styles.css               디자인 시스템·히어로 모션·핀 펄스·바텀시트 (이미지 의존 없음)
├─ app.js                   화면 로직 (지수 계산·코스 추천·주차 판정·지도·시트)
├─ api-config.js            데이터 접근 어댑터. mode:'sample' | 'live', 키·URL·태그 이름
├─ assets/                  스팟 일러스트 4장 (생성 이미지)
├─ vendor/leaflet/          Leaflet 1.9.4 (unpkg 배포본 그대로)
├─ data/
│  ├─ raw/                  data.go.kr CSV 원본(CP949) + UTF-8 정규화본
│  ├─ parking_history.json  주차장 혼잡도 699행 → JSON
│  ├─ lawn.json             잔디시설정보 8행 → JSON
│  ├─ faq.json              자주 묻는 질문정보 49행 → JSON
│  ├─ gates.json            문 ↔ 주차구역 매핑(기관 홈페이지 안내 표)
│  ├─ geo.json              공원 경계·수면·산책로·출입문·스팟·코스 좌표 (OSM/카카오)
│  ├─ sample_*.json         실시간 주차·날씨·공연·수목·장미·생태 갤러리 스펙 샘플
│  └─ data-bundle.js        위 JSON 을 <script> 로 읽히게 묶은 파일(file:// 대응, 자동 생성)
└─ tools/
   ├─ build-data.py         CSV → JSON (원본은 그대로 두고 UTF-8 정규화본 생성)
   ├─ make-samples.py       실시간 주차현황 샘플 생성(이력 혼잡도 × 용량 × 시연 편차)
   ├─ fetch-geo.py          OSM/Nominatim/Overpass + 다익스트라 → data/geo.json (1회 실행)
   ├─ build-bundle.py       data/*.json → data/data-bundle.js
   └─ preview-test.py       로컬 서버 + 실제 브라우저 검증(콘솔·탭·지도·폴백·스크린샷)
```

`data/*.json` 을 고쳤다면 `python3 tools/build-bundle.py` 를 다시 실행하세요(화면은
`data-bundle.js` 를 읽습니다). 지도 좌표를 다시 만들려면 `python3 tools/fetch-geo.py`
(네트워크 필요, 결과 `geo.json` 은 저장소에 커밋).

## 5. 실제로 받은 CSV 3종

| 데이터 | 원본 파일 | 행수 | 기준일 | 쓰는 곳 |
|---|---|---|---|---|
| 주차장 혼잡도 정보 (15164156) | `한국체육산업개발주식회사_주차장 혼잡도 정보_20260812.csv` | **699** | 2025-02-12 ~ 2026-08-12 | 지도 핀 등급·바텀시트 |
| 잔디시설정보 (15143220) | `…_잔디시설정보_20250512.csv` | **8** | 2025-05-12 배포 | 안내 탭 잔디 상태 |
| 자주 묻는 질문정보 (15089962) | `…_자주 묻는 질문정보_20260819.csv` | **49** | 2026-08-19 배포 | 안내 탭 FAQ |

원본 바이트는 `data/raw/*.csv` 에, 같은 내용의 UTF-8 정규화본은 `*.utf8.csv` 에 남겼습니다.

### 원본을 읽으면서 확인된 것

- **주차장 혼잡도 정보는 주기적 시계열이 아니라 기록(이벤트 로그)입니다.** 699행이 90여 날짜에
  흩어져 있어 같은 요일·시간대 표본이 몇 건뿐입니다. 그래서 화면에 **표본 수를 항상 같이**
  적고, 3건 미만이면 시간대를 ±3시간으로 넓혔다고 밝힙니다.
- **최신 행이 2026-08-12 입니다.** 포털 표기 수정일은 2026-09-22(월간 갱신)이지만 최근 4주
  신규 행은 0건이라, 그 사실을 숨기지 않고 발표 자료에 그대로 씁니다.
- **잔디시설정보의 `개방시간` 열에는 시각이 아니라 라벨이 들어 있습니다.** 실제 내용은
  `개방내용` 열(`연중 상시개방`, `06-01 ~ 10-31`, `11-01 ~ 익년05-31`)이고, 화면은 그 열을
  근거로 오늘 상태를 계산합니다. 8행 중 나홀로나무가 두 번 등재되어 고유 장소는 7곳입니다.
- **FAQ 는 `제목`=질문, `내용`=답변** 구조입니다(카테고리: 한국체육산업개발 25 · 올림픽공원 17 ·
  미사경정공원 7). 답변 원문을 줄이지 않고 그대로 보여 줍니다.
- **CSV 에는 주차구역 코드(P1A·P1B·P2…)만 있고 출입문 정보가 없습니다.** 문별 묶음은 기관
  홈페이지 [주차안내](https://www.ksponco.or.kr/olympicpark/parkingInfo?mid=a20111000000) 표를
  `data/gates.json` 에 옮겼습니다(북2문 P4·P5 / 동2문 P1B·P2·P3·테니스장(P11) / 남2문 P1A·P6·P7).
- **서2문은 혼잡도 등급을 내지 않습니다.** 같은 표에 서2문이 `올림픽파크텔, 지상·지하(1·2)주차장`
  으로 나오지만, CSV 에는 그 구역 코드가 없습니다. 그래서 지도에 핀은 찍되 회색
  `자료 없음`으로 두고, "왜 등급이 없는지"를 바텀시트에 적었습니다. **수를 지어내지 않는 쪽을
  택했습니다.**

## 6. 오픈API 5종 + 기상청: 확인된 스펙과 가정

data.go.kr 오픈API 5종은 모두 **API 유형 LINK** 라서 포털에 요청/응답 명세표가 없습니다.
확인되는 이름은 그대로 쓰고, 확인되지 않은 태그 이름은 `api-config.js` 의 `tags` 로 바꿔 끼웁니다.

| 데이터 | 확인된 것 | 가정한 것(명세서로 확정 필요) |
|---|---|---|
| 실시간 주차현황 | 요청 `ApiKey`, 출력 `parking_sum`(주차대수), XML, "동2문/남2문/북2문 주차구역" | `item` 반복 구조, 구역 태그 `parking_id`, 갱신시각 `updt_dt` |
| 올림픽공원 공연정보 | `행사명` `행사기간` `행사장소` `홈페이지URL` | 회차별 `행사시간` 필드 존재 |
| 올림픽공원 수목정보 | `수목명` `수목종류` `설명`, 182건 | `수목종류` 값 체계 |
| 올림픽공원 장미광장 | `장미명` `품명` `계통` `꽃색` `육성국` `특성` | `계통` 국문 표기 방식 |

## 7. 계산 규칙 (화면의 `데이터·계산` 시트와 같은 내용)

**산책 지수** — 100점에서 항목별 감점, 5점 단위 반올림.
기온(33℃↑ −15 / 30~33℃ −8 / 0~5℃ −5 / −5℃↓ −15) · 강수(비 −20, 눈 −25, 소나기 −15,
시간당 3mm↑ −5) · 하늘(흐림 −3, 구름많음 −1) · 바람(8m/s↑ −10, 4~8m/s −5) ·
예보(3시간 내 강수확률 60%↑ −10). 75점↑ "지금 출발하기 좋습니다", 50~74 "걷기 무난합니다",
50점↓ "다른 날을 권합니다".

**코스 추천** — 비·바람·기온·개화기·잔디 통제 여부로 코스별 가점·감점 후 정렬.
비가 오면 **실내 코스에 +6**, 숲길(그늘 0.8↑)에 +3, 포장로에 +1. 맑은 날에는 실내 코스에 −3,
장미 개화기(5~10월)가 아니면 장미 코스에 −1, 88마당이 통제 기간이면 −1.
추천 입구는 **그 코스의 출발 문**이고, 그 문이 붐비면 가장 여유로운 문으로 바꿉니다.

**주차 등급**
1. 지금 값 = 실시간 구역별 주차대수의 30분 이동평균(5분 간격 6회 이상).
2. 통상 값 = 이력 혼잡도 평균(원활 0·혼잡 1·만차 2)을 점유율 35~95%로 옮겨 기관 안내
   가능 주차대수를 곱한 값.
3. 등급 = (지금 − 통상) ÷ 통상 이 **−15% 이하 여유 / +15% 이상 붐빔 / 사이 보통**.
4. 같은 요일유형·같은 시간대(±1시간) 표본이 문별 3건 미만이면 ±3시간으로 넓히고, 넓혔다는
   사실을 바텀시트에 적습니다.

> 포화율(%)은 계산하지 않습니다 — 실시간 주차현황이 구역별 대수만 주고 총 면수를 주지 않기
> 때문입니다. 용량이 기관 안내에 없는 구역(P1A·P1B 분할, P3·P8~P10)은 "용량 추정" 표시를 답니다.

## 10. 남은 일 · 기획서와 달라진 점

1. **API 키 발급·명세 확정**: 실시간 주차현황·공연정보·수목정보·장미광장·생태공원 갤러리 활용
   신청 후 `tags` 이름을 확정해야 live 전환이 끝납니다.
2. **서2문 혼잡도**: 기관이 올림픽파크텔 주차장의 구역 코드를 공개하면 핀 등급을 계산할 수
   있습니다. 지금은 `자료 없음`으로 두고 그 이유를 화면에 적었습니다.
3. **코스 거리 표기**: 기획서 예시는 2.4 / 1.8 / 1.2km 였지만, 실제 OSM 보행로로 계산한 값은
   2.5 / 2.7 / 1.5km 입니다(출입문에서 코스 시작점까지 걷는 거리 포함). 화면에는 **계산된 값**을
   적었고, 실내 코스는 네이버 도보 길찾기 1.5km 와 일치합니다.
4. **주차 통상 대수의 용량 출처**: P1A·P1B 분할값과 P3·P8~P10 용량은 추정입니다. 기관이 구역별
   면수를 개방하면 그 값으로 교체하면 됩니다.
5. **정적 사이트의 5분 갱신**: 실시간 주차를 실제로 5분마다 갱신하려면 예약 실행(에잇 함수 등)이
   붙어야 합니다. 지금은 시연 스냅샷 7회로 30분 이동평균을 재현합니다.
